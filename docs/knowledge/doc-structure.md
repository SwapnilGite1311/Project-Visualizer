# Documentation structure

This page says where each kind of document goes.

## Levels

1. Vision and roadmap
2. Requirements and NFR
3. Architecture and decisions
4. Component and domain designs
5. Module READMEs and API docs
6. User guide

## Where things go

| Document type | Folder |
|---|---|
| Vision, features, roadmap | `docs/vision/` |
| Environment setup | `docs/setup/` |
| Personas, stories, acceptance criteria | `docs/requirements/` |
| Non-functional requirements | `docs/nfr/` |
| System architecture | `docs/architecture/` |
| Component designs | `docs/components/` |
| Data and domain model | `docs/domain/` |
| ADRs and versions | `docs/decisions/` |
| Coding standards and workflow | `docs/standards/` |
| QA and testing | `docs/testing/` |
| Documentation and knowledge process | `docs/knowledge/` |
| Build plan | `docs/plan/` |
| Task status files | `docs/status/` |
| User research | `docs/research/` |
| Phase sign-offs | `docs/signoff/` |
| End-user guide | `docs/user-guide/` |
| Design diary | `docs/diary/` |
| Security documents | `docs/security/` |

## Module READMEs

Each engine module, desktop feature and service may have a `README.md` inside its own folder, owned by that module.
