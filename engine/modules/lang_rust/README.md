# lang_rust — Rust

`RustAdapter` (id `rust`, files `.rs`), grammar `tree-sitter-rust` v0.23.2 (`engine/third_party/ts_rust`).

Detected: functions, structs and enums (as classes), traits (as interfaces, shown as classes), methods in `impl` blocks, trait implementations (as inheritance), `mod x;` and `use` imports, calls (`f()`, `Type::f()`, `value.f()`), and complexity (`if`, `match` arms, `while`, `for`, `loop`).

## Modules

A file's module path follows Cargo's layout:

| File | Module |
|---|---|
| `src/main.rs`, `src/lib.rs` | `crate` |
| `src/store.rs` | `crate::store` |
| `src/api/mod.rs` | `crate::api` |
| `src/api/routes.rs` | `crate::api::routes` |
| `tests/it.rs` (outside `src/`) | `tests::it` |

`mod store;` links the declaring file to `store.rs` (or `store/mod.rs`) next to it. `use crate::…`, `use self::…` and `use super::…` are resolved to the module, or to the item when the last part names a struct, enum, trait or function in that module (`use crate::store::Store` → the `Store` struct). Anything else is an external crate named by its first part (`use std::collections::HashMap` → `std`, `use serde::Serialize` → `serde`). A name brought in by `use` is followed in calls: after `use crate::store::Store;`, `Store::new()` links to `Store.new`.

## impl blocks

Functions in `impl Store { … }` become methods `Store.new`, `Store.add` of `Store` (when `Store` is declared in the same file; otherwise they stay functions named `Store.new`). `impl Countable for Store` is shown as `Store` inheriting from `Countable`, and the functions in it become methods of `Store`. Calls inside methods are recorded as coming from those methods.

## Limits

- Macro bodies are not analyzed (`println!`, `vec!`, `tokio::main`…), and code generated by derive macros does not appear.
- Methods are resolved by name only: a call on a value (`s.add()`) is not linked, because the type of `s` is not inferred; calls through a type path (`Store::new()`) are.
- `use` groups (`use crate::a::{B, C}`) and glob imports (`use crate::a::*`) are not followed.
- Workspace crates (other members of a Cargo workspace) are not linked to each other; they appear as external crates.
- Generic `impl<T> Trait for Wrapper<T>` blocks are not attached (only plain type names are).
